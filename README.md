## What This Project Does

**The one-paragraph summary you can say to your supervisor:**

> We integrated three complementary cancer databases into a single knowledge graph.
> CancerMine provides literature evidence for which genes drive which cancers (and how).
> COSMIC provides experimental evidence — actual DNA mutations found in 1.4 million real patient tumours.
> HeNeCOn provides formal clinical definitions for Head & Neck Cancer concepts.
> Together they create a 176,956-node graph where a single query can answer:
> *"Which genes are literature-confirmed drivers of lung cancer, also show somatic mutations
> in lung tumour samples, and connect to formal clinical staging concepts?"*
> This is impossible with any single database alone.

**Why a knowledge graph and not a table?**

A table can answer *"what genes are linked to cancer X?"*
A knowledge graph can answer *"what genes are linked to cancer X, and also mutated in tissue Y,
and also neighbours of gene Z which we already know is a driver, and have at least 50 citations
supporting their role?"* — all in one traversal. Graph Neural Networks (GNNs) can then learn
from this structure directly, without handcrafted features.

### Database 1 — CancerMine (Literature Evidence Layer)

**What it is in plain English:**
A computer program called *Kindred* read millions of medical papers and highlighted every sentence saying things like *"gene X is a driver of cancer Y"* or *"gene X suppresses cancer Y."* It counted how many different papers said the same thing, giving a confidence score per gene-cancer-role triple.

| Property | Details |
|---|---|
| **Type** | NLP text-mined knowledgebase |
| **Format** | TSV (tab-separated values) |
| **Size used** | 38,204 gene–cancer–role triples |
| **Genes** | 1,218 unique genes |
| **Cancer types** | 426 distinct types |
| **Licence** | CC0 — completely free, no login |
| **DOI** | [10.1038/s41592-019-0422-y](https://doi.org/10.1038/s41592-019-0422-y) |
| **Download** | `python -m zenodo_get 10.5281/zenodo.1156241` |

**Key columns in `cancermine_collated.tsv`:**

| Column | Type | What it means | Example |
|---|---|---|---|
| `gene_normalized` | string | Official gene symbol (HUGO) | `TP53` |
| `cancer_normalized` | string | Normalised cancer type name | `breast cancer` |
| `cancer_id` | string | Disease Ontology ID | `DOID:1612` |
| `role` | enum | Gene's role in this cancer | `Driver` / `Oncogene` / `Tumor_Suppressor` |
| `citation_count` | integer | Papers supporting this triple | `1842` |
| `gene_entrez_id` | integer | NCBI Entrez Gene ID | `7157` (TP53) |

**How it becomes part of the KG:**
- Each `gene_normalized` → Gene node (blue)
- Each `cancer_normalized` → Cancer node (orange)
- Each row → edge with `relation = role`, `weight = log10(citation_count) / max_per_cancer`

**Why the citation count matters:**
1 paper could be wrong. 1,842 independent research teams finding the same thing is very strong evidence. The citation count becomes the **edge weight** — thicker lines in the visualisation = more confident associations.

### Database 2 — COSMIC (Experimental Evidence Layer)

**What it is in plain English:**
Scientists took real tumour samples from 1.4 million cancer patients, read their DNA, and wrote down every mutation they found. COSMIC is the official catalogue — like an enormous spreadsheet with one row per DNA typo found in a cancer cell.

**Two files are used:**

#### File A — Cancer Mutation Census (CMC)
All somatic mutations across all genes. 38M+ rows. Used for: which genes are mutated, how often, and how damaging.

| Property | Details |
|---|---|
| **File** | `CancerMutationCensus_AllData_v103_GRCh37.tsv` |
| **Size** | 1.7 GB |
| **Rows** | 38M+ (we load 300,000 for speed) |
| **Version** | v103, GRCh37 genome build |

**Key columns in CMC (v103 exact names):**

| Column | What it means | Example |
|---|---|---|
| `GENE_NAME` → renamed `GENE_SYMBOL` | Gene carrying this mutation | `TP53` |
| `CGC_TIER` → renamed `TIER` | Cancer Gene Census confidence: 1=gold standard, 2=likely | `1` |
| `Mutation CDS` → `MUTATION_CDS` | DNA-level change (HGVS notation) | `c.817C>T` |
| `Mutation AA` → `MUTATION_AA` | Protein-level change | `p.R273H` |
| `Mutation Description AA` → `MUTATION_DESCRIPTION` | Human-readable consequence | `Substitution - Missense` |
| `MUTATION_SIGNIFICANCE_TIER` → `SIGNIFICANCE_TIER` | Per-mutation significance rating | `Tier1 / Tier2 / Other` |
| `COSMIC_SAMPLE_TESTED` → `SAMPLES_TESTED` | Samples screened for this gene | `681` |
| `COSMIC_SAMPLE_MUTATED` → `SAMPLES_MUTATED` | Samples where mutation was found | `1` |
| `ONC_TSG` | Oncogene/TSG classification from CGC | `oncogene / TSG` |
| `MIN_SIFT_PRED` → `SIFT_PRED` | Functional impact: D=Deleterious, T=Tolerated | `D` |
| `MIN_SIFT_SCORE` → `SIFT_SCORE` | SIFT score 0–1 (< 0.05 = damaging) | `0.001` |
| `DISEASE` | Associated cancer type | `lung adenocarcinoma` |
| `CLINVAR_CLNSIG` | ClinVar clinical significance | `Pathogenic` |
| `GENOMIC_MUTATION_ID` | Stable COSV identifier | `COSV66110236` |

> **⚠️ Important for v103:** CMC does NOT have PRIMARY_SITE, HISTOLOGY, or FATHMM columns.
> These existed in earlier COSMIC versions. In v103, SIFT replaces FATHMM for pathogenicity.

#### File B — MutantCensus / Cancer Gene Census (CGC)
The 723 most confidently cancer-causing genes, with per-sample mutation records.

| Property | Details |
|---|---|
| **File** | `Cosmic_MutantCensus_v103_GRCh37.tsv` |
| **Size** | 522 MB |
| **Genes** | 723 confirmed cancer drivers |

**Key columns in CGC (v103 exact names):**

| Column | What it means | Example |
|---|---|---|
| `GENE_SYMBOL` | HGNC gene symbol | `KMT2C` |
| `GENOMIC_MUTATION_ID` | Stable COSV mutation ID | `COSV109572201` |
| `MUTATION_CDS` | DNA-level change | `c.6676A>G` |
| `MUTATION_AA` | Protein-level change | `p.R2226G` |
| `MUTATION_DESCRIPTION` | Mutation type | `missense_variant` |
| `CHROMOSOME` | Chromosome location | `7` |
| `GENOME_START` | GRCh37 genomic position | `151878269` |
| `COSMIC_SAMPLE_ID` → `SAMPLE_ID` | Tumour sample identifier | `COSS2997395` |
| `MUTATION_SOMATIC_STATUS` → `SOMATIC_STATUS` | Confirms somatic (not germline) | `Confirmed somatic variant` |
| `HGVSP` | HGVS protein notation | `ENSP00000262189.6:p.Arg2226Gly` |

> **CGC has no PRIMARY_SITE, HISTOLOGY, TIER, or FATHMM columns in v103.**

**How COSMIC becomes part of the KG:**
- Each `GENE_SYMBOL` → Gene node (reuses existing if already from CancerMine)
- `MUTATION_DESCRIPTION` aggregated → mutation type KG property
- `GENOMIC_MUTATION_ID` → Mutation node (amber) connected via `has_mutation` edge
- Tissue data (where available) → Tissue node connected via `mutated_in` edge

### Database 3 — HeNeCOn (Clinical Knowledge Layer)

**What it is in plain English:**
A team of doctors wrote an official dictionary of every clinical concept in Head & Neck Cancer — every anatomy term, every stage name, every treatment type — in a machine-readable format. It is an OWL ontology: not just a list of words, but a map of how concepts relate to each other.

| Property | Details |
|---|---|
| **Type** | OWL2 DL ontology |
| **Format** | `.owl` (XML/RDF serialisation) |
| **Classes** | 502 clinical concepts |
| **Definitions** | 283 formal semantic definitions |
| **External mappings** | SNOMED CT · ICD-O-3 · NCIt · UBERON |
| **Licence** | CC BY — free with attribution |
| **DOI** | [10.1016/j.ijmedinf.2023.105284](https://doi.org/10.1016/j.ijmedinf.2023.105284) |

**The 5 clinical domains it covers:**

| Domain | Examples |
|---|---|
| **Anatomy** | Oral cavity, larynx, pharynx, tongue, salivary glands |
| **Staging** | T1–T4 (tumour size), N0–N3 (lymph node spread), M0–M1 (metastasis) |
| **Histology** | Squamous cell carcinoma, adenocarcinoma, lymphoma |
| **Treatment** | Surgery, radiotherapy, chemotherapy, immunotherapy |
| **Risk factors** | HPV, tobacco, alcohol, EGFR mutation |

**Why an ontology is different from a database:**
A database says *"T2 stage exists."*
An ontology says *"T2 stage IS A T stage, which IS A staging concept, which IS A clinical concept."*
Computers can follow these "is-a" links to reason — if a drug targets "carcinoma," it logically applies to "squamous cell carcinoma" and "adenocarcinoma" too, without being told explicitly.

**How HeNeCOn becomes part of the KG:**
- Each `rdfs:label` (class name) → HNC Concept node (purple)
- `rdfs:subClassOf` triples → `subclassof` edges (grey, hierarchy)
- Label matching with CancerMine/COSMIC → `mapped_to_ontology` edges (orange dashed)

**How to get HeNeCOn:**
Request from `giuseppe.fico@upm.es` or download via ScienceDirect supplementary materials (DOI above). The `.owl` file goes into the `hencon/` folder.

## Knowledge Graph — How It Is Built

### Graph Type
**Directed, heterogeneous, multi-relational property graph**
- Built with **NetworkX** `DiGraph`
- Exported as GraphML, CSV, and interactive HTML

### Node Types

| Node Type | Colour | Real count | Source |
|---|---|---|---|
| 🔵 **Gene** | `#4C9BE8` Blue | ~1,218 unique | CancerMine + COSMIC |
| 🟠 **Cancer** | `#E8724C` Coral | ~426 types | CancerMine |
| 🟢 **Tissue** | `#52B788` Teal | ~30 sites | COSMIC |
| 🟡 **Mutation** | `#F0C040` Amber | ~130,000+ | COSMIC (COSV IDs) |
| 🟣 **HNC Concept** | `#8E6BBF` Purple | 502 | HeNeCOn OWL |

**Total: 176,956 nodes · 200,727 edges**

### Edge (Relation) Types

| Relation | Colour | Direction | Source | What it means |
|---|---|---|---|---|
| `driver` | 🔴 Red | Gene → Cancer | CancerMine | Broken gene actively pushes cells toward cancer |
| `oncogene` | 🟡 Yellow | Gene → Cancer | CancerMine | Over-active gene drives uncontrolled cell growth |
| `tumor_suppressor` | 🟢 Green | Gene → Cancer | CancerMine | Broken gene removes a brake on cell division |
| `mutated_in` | 🩵 Cyan | Gene → Tissue | COSMIC | Somatic mutations detected in this tissue |
| `has_mutation` | 🟣 Purple | Gene → Mutation | COSMIC | This COSV variant found in this gene |
| `subclassof` | ⚪ Grey | HNC → HNC | HeNeCOn | Child concept is a specialisation of parent |
| `mapped_to_ontology` | 🟠 Orange | Gene/Cancer → HNC | Cross-link | Label matches a HeNeCOn clinical concept |

### Integration Logic — How the Databases Are Joined

```
Gene "TP53" appears in all 3 databases:
  CancerMine:  TP53 --[driver]--> breast cancer  (1,842 papers)
  COSMIC:      TP53 --[mutated_in]--> lung tissue  (from 300k rows)
               TP53 --[has_mutation]--> COSV51765119  (specific DNA change)
  HeNeCOn:     "breast cancer" label matches HeNeCOn class
               TP53 --[mapped_to_ontology]--> HeNeCOn:BreastCarcinoma

Result: One TP53 node with ALL connections from ALL 3 databases.
```

### Graph Schema

```
                   ┌─────────────────────────────────┐
                   │      HeNeCOn OWL Ontology        │
                   │  [HNC Concept]──subClassOf──▶[HNC]│
                   └────────────────┬────────────────-─┘
                                    │ mapped_to_ontology (orange)
                                    ▼
 ┌────────────┐   driver (red)    ┌────────────┐
 │    GENE    │ ─────────────────▶│   CANCER   │
 │  (blue)    │ ─oncogene (yel)──▶│  (coral)   │
 │            │ ─tumor_sup (grn)─▶│            │
 └─────┬──────┘                   └────────────┘
       │ mutated_in (teal)
       ▼
 ┌────────────┐
 │   TISSUE   │  (from COSMIC primary sites)
 │  (green)   │
 └────────────┘

 ┌────────────┐
 │    GENE    │──has_mutation (purple)──▶ [MUTATION] (amber)
 └────────────┘                           COSV stable ID
```

### Edge Weight Calculation

CancerMine edges carry a normalised weight used for ML:
```python
weight = log10(citation_count + 1) / max_log_per_cancer_type
# Range: 0.0 to 1.0
# 1.0 = the most-cited gene-role pair for that cancer
# 0.1 = a weakly supported association
```

## Script Reference

### 1. `build_cancer_kg.py`

**What it does:** Reads all three databases and builds the complete knowledge graph.

**Step-by-step internally:**
1. Load `cancermine_collated.tsv` → create Gene nodes, Cancer nodes, and role edges
2. Load `CancerMutationCensus_AllData_v103_GRCh37.tsv` (300k rows) → add Tissue nodes, Mutation nodes, `mutated_in` and `has_mutation` edges
3. Load `Cosmic_MutantCensus_v103_GRCh37.tsv` (300k rows) → add more Gene→Tissue connections for CGC genes
4. Parse `HeNeCOn.owl` with rdflib → add HNC Concept nodes and `subclassof` edges
5. Label-match CancerMine/COSMIC node labels against HeNeCOn `rdfs:label` → add `mapped_to_ontology` edges
6. Write outputs: `cancer_kg_nodes.csv`, `cancer_kg_edges.csv`, `cancer_kg.graphml`, `cancer_kg.html`

```bash
python build_cancer_kg.py
# Expected output:
#   Building CancerMine graph...  [OK]
#   Building COSMIC graph...      [OK]
#   Parsing HeNeCOn OWL...        [OK]
#   Total: 176,956 nodes | 200,727 edges
```

### 3. `build_all_subgraphs.py`

**What it does:** Extracts 5 different views of the knowledge graph into one unified HTML explorer with tabbed navigation.

**Why it exists:** The full KG has 176,956 nodes — impossible to understand all at once. This script creates meaningful subsets that answer specific questions: "What does the CancerMine-only graph look like?" or "How does TP53 connect to everything around it?"

**The 5 tabs it creates:**

#### Tab 1 — CancerMine KG (blue)
Shows only the gene→cancer literature evidence subgraph.
- **Nodes:** Top 60 genes by citation degree + their cancer connections (≤120 total)
- **Edges:** Only `driver`, `oncogene`, `tumor_suppressor` edges
- **Edge thickness:** Proportional to citation count (thicker = more papers)
- **What to notice:** TP53 is the biggest node (most citations). Red edges dominate because most well-studied genes are drivers. Genes like NOTCH1 have both green AND yellow edges — context-dependent roles.

#### Tab 2 — COSMIC KG (orange)
Shows only the gene→tissue mutation evidence subgraph.
- **Nodes:** Top 50 mutated genes + tissues they mutate in + up to 30 mutation variants
- **Edges:** Only `mutated_in` (teal, gene→tissue) and `has_mutation` (purple, gene→mutation variant)
- **What to notice:** KRAS has thick teal edges to lung, pancreas, colorectal — these are its dominant cancer tissues. Amber circles are individual COSV mutation IDs (unique stable identifiers for each specific DNA change).

#### Tab 3 — HeNeCOn KG (purple)
Shows only the OWL ontology hierarchy.
- **Nodes:** 120 HNC concept classes from the ontology
- **Edges:** Only `subclassof` (grey, is-a hierarchy)
- **What to notice:** The hierarchy flows from broad concepts (HNC disease) down to specific ones (T2 stage laryngeal squamous cell carcinoma). This is what enables clinical reasoning — if you find genes linked to "carcinoma," they apply to all its subtypes automatically.

#### Tab 4 — Combined KG (yellow/gold)
Shows all 3 databases merged, anchored on 3 seed nodes.
- **Seeds:** TP53 (gene) + head-and-neck cancer (cancer node) + top HeNeCOn concept
- **Shows everything within 1 hop of any seed**
- **What to notice:** Look for nodes with BOTH teal edges (COSMIC) AND red/green/yellow edges (CancerMine). These double-validated genes have the strongest evidence. Orange dashed edges (mapped_to_ontology) are the unique cross-database bridges.

#### Tab 5 — Curated Subgraphs (deep dives)
4 hand-curated ego-networks with step-by-step explanations:

| Subgraph | Seed(s) | Key insight |
|---|---|---|
| **TP53** | GENE:TP53 | Most connected gene in KG. Red/green edges = driver/TSG context-dependent |
| **KRAS** | GENE:KRAS | Predominantly yellow (oncogene). Teal edges = COSMIC tissue mutations |
| **Head & Neck Cancer** | HNC cancer node | Only cancer with HeNeCOn cross-links. NOTCH1 paradox visible |
| **Breast Cancer** | Breast + BRCA1 + BRCA2 | Multi-seed. BRCA1/2 green TSG edges + HER2/PIK3CA oncogene context |

**How the step-by-step explanation works:**
Click a subgraph card, then use ← → arrows to walk through 4–5 explanation steps. Each step highlights what to look for in the graph at that moment — like a guided tour.

**How the node inspector works:**
Click any node in the graph. The bottom-left panel shows:
- Node type and source database
- Number and types of connections
- Definition (if from HeNeCOn)
- Clickable neighbour list (clicking centres the view on that neighbour)

### 4. `serve_kg.py`

**What it does:** Starts a local web server on port 8000 so that `vis-network` (the graph rendering library) can load from CDN.

**Why it is needed:**
Chrome blocks external CDN requests (`cdnjs.cloudflare.com`) when a page is opened as a `file://` URL — a security restriction. When you run `python serve_kg.py`, the pages are served as `http://localhost:8000/...` which Chrome treats as a regular website, allowing CDN scripts to load.

**The symptom without it:** The graph canvas appears but is completely empty (black). Node count shows 0. This is because `vis` is `undefined` — the rendering library never loaded.

```bash
python serve_kg.py
# Starts server at http://localhost:8000/
# Automatically opens Chrome to the subgraph explorer
# Press Ctrl+C to stop
```

All your KG HTML files work from this server:

| URL | Page |
|---|---|
| `http://localhost:8000/kg_output/all_subgraphs.html` | Per-database subgraph explorer (5 tabs) |
| `http://localhost:8000/kg_output/cancer_kg_enhanced.html` | Full 176k-node KG (enhanced) |
| `http://localhost:8000/kg_output/cancer_kg.html` | Full KG (basic) |
| `http://localhost:8000/db_profiles/00_overview_dashboard.html` | Database profiler dashboard |

## ML / GNN Usage

The knowledge graph is designed to feed directly into GNN frameworks:

```python
import pandas as pd
import networkx as nx
from torch_geometric.utils import from_networkx

# Load the graph
nodes = pd.read_csv('kg_output/cancer_kg_nodes.csv')
edges = pd.read_csv('kg_output/cancer_kg_edges.csv')
G = nx.read_graphml('kg_output/cancer_kg.graphml')

# Convert to PyTorch Geometric
data = from_networkx(G)
# data.x            = node feature matrix
# data.edge_index   = connectivity (2 × num_edges)
# data.edge_attr    = edge weights / relation types
```

**Suggested ML tasks:**

| Task | Graph framing | Suggested model |

| Cancer gene classification | Node classification: predict driver/oncogene/TSG for unlabelled genes | GraphSAGE, GAT |

| Cancer subtype clustering | Node clustering on cancer nodes by shared gene profiles | GraphAutoEncoder |
| Drug target discovery | Identify hub genes in specific cancer subgraphs | Degree + betweenness centrality |
