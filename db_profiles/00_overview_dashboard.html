Why Each Database Matters
CancerMine — Literature Evidence
Provides the functional role labels for each gene-cancer pair. Without CancerMine, we would have mutation data but no understanding of whether a mutation is a driver, oncogene, or tumour suppressor. It is the semantic layer of the KG.
COSMIC — Biological Evidence
Provides experimental mutation-level data from 1.4M real patient tumours. Without COSMIC, we would have literature claims but no direct genomic evidence. It is the experimental validation layer of the KG.
CGC — Validated Driver Set
Provides the gold-standard list of 723 proven cancer driver genes with Tier 1/2 confidence. It acts as the quality filter — genes in the CGC are the highest-priority targets for the ML prediction model.
HeNeCOn — Clinical Semantics
Provides formal clinical definitions for HNC concepts — staging, anatomy, treatment. Without HeNeCOn, the KG cannot bridge gene evidence to clinical decision-making. It is the clinical knowledge layer.
How the Databases Connect — Integration Logic
The three databases are integrated via shared entity labels: gene symbols (e.g. TP53) appear in both CancerMine and COSMIC. Cancer type names (e.g. "head and neck cancer") appear in CancerMine and map to HeNeCOn ontology classes. This creates a unified multi-relational graph where a single query can answer: "Which genes are literature-confirmed drivers of HNC, also have somatic mutations in head tissue, and map to a formal staging concept?" — impossible with any single database alone.
